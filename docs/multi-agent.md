# 多智能体实验手册：把学习单位、权限和对手人口写清楚

**状态：研究设计与外部接入指南。工作台没有原生 MARL 训练器，本文也不报告新的 MARL 效能结果。** MAPPO、IPPO、QMIX、VDN、MADDPG 及 PettingZoo/SMACv2 目录项均为 `reference_only`。[设计卡](../examples/designs/marl-crossplay.json) 是待落实的计划，不能交给 `run` 当作可执行协议。

## 1. 先确定游戏和预算单位

先写完全合作、二人零和或一般和；再写谁学习、谁固定、个体奖励如何形成团队目标。若指标定义为一次团队 reward，就不能再按 agent 数重复求和；个体 reward 求和则应说明人数变化是否改变目标。角色、合法动作 mask 和通信权限也属于任务定义。

同时保存三个时钟：世界联合转移 `T_joint`、真实执行的 agent 动作数 `T_agent=Σₜ|Aₜ|`、学习器更新数。AEC 单次调用、Parallel 联合动作、vector env 批次不是同一个“step”。若有 `N` 个独立副本，每个推进 `T` 次且始终有 `M` 个行动者，联合转移总数为 `NT`，agent 动作数为 `MNT`；动态 agent 数和轮流行动需按实际日志累加。分开计量训练、评价、对手生成、规划模型查询、通信字节与延迟。

**独立统计单位通常是完整训练团队/学习人口的独立初始化与生命期。** 一队里的多个 agent、同一人口的多场比赛和多个向量环境不是独立算法重复。冻结模型后大量比赛可以估计“这些模型对该对手池”的条件表现；不能消除训练不确定性。若多组 focal agent 共用一批训练出来的队友，交叉矩阵的行列都有依赖：按训练人口/队友来源聚类，或在每个外层种子重新生成整个队友池。基础 `compare` 只做固定环境下的 paired-seed 摘要，不提供这种交叉随机效应推断。[Gorsane 等，2022](https://proceedings.neurips.cc/paper_files/paper/2022/hash/249f73e01f0a2bb6c8d971b565f159a7-Abstract-Conference.html)

## 2. 集中训练的权限不能流入分散执行

为每个张量写明 `actor_at_execution`、`critic_at_training` 或 `diagnostics_only`。CTDE 可以让训练 critic 读取全局状态和联合动作，但部署 actor 只能读取已声明的本地历史与合法消息。测试时给 actor 传全局状态、用中央 hidden 初始化本地 RNN、按隐藏队友 ID 选择策略，都改变部署权限。中央训练梯度本身是 CTDE 的合法机制；应检查的是执行时的信息通路。

参数共享与集中信息是两条轴：IPPO 可共享 actor 参数，也可每个 agent 独立参数；“independent”不能自动读成“不共享”。共享时还要写 agent/role ID、异构角色头、归一化汇总范围及每轮数据量。不共享方法有更多总参数，应同时展示总容量、每 agent 容量和总计算成本。

| 方法 | 主要结构 | 不能忽略的合同 |
|---|---|---|
| [IPPO](https://arxiv.org/abs/2011.09533) | PPO 的本地 value 估计 | 参数共享、局部观测、优势与 reward 约定 |
| [MAPPO](https://arxiv.org/abs/2103.01955) | PPO + 集中 value 输入 | critic 权限、agent 死亡处理、训练轮数与 clip；作者实现默认共享策略 |
| [VDN](https://arxiv.org/abs/1706.05296) | `Q_tot=ΣᵢQᵢ` | 团队目标、局部效用与 replay 时序；效用不等于真实个体贡献 |
| [QMIX](https://proceedings.mlr.press/v80/rashid18a.html) | 单调 mixing，`∂Q_tot/∂Qᵢ≥0` | 状态条件化 mixer、可用动作与分散贪心一致性条件 |
| [MADDPG](https://arxiv.org/abs/1706.02275) | 集中 critic、分散 actor | 连续/离散动作适配、联合 replay、对手策略变化 |

这些是方法定位，不是通用排名。原方法、同基座移植和内部控制分别命名；作者默认配置必须绑定版本。MAPPO 的实现和超参细节应查[作者仓库](https://github.com/marlbenchmark/on-policy)，不能用一份单智能体 PPO 默认值代替。

## 3. 先用微型游戏检查接口

[PettingZoo AEC](https://pettingzoo.farama.org/api/aec/) 按所选 agent 依次行动，`last()` reward 与即时 rewards 字典的累计语义不同；不能每轮两者都相加。[Parallel](https://pettingzoo.farama.org/api/parallel/) 提交同时行动的字典。只有满足对应周期更新限制时才能转换接口；将顺序游戏强行并行会改变后手可见的信息。

微测至少包含：两 agent 一次联合奖励、先后手不同观察、某 agent 提前离开、时间截断、全体结束、角色重新加入和一次换队友。核实：

- 用稳定 agent 身份映射观测/动作/hidden，不能依赖字典遍历次序；缺席者不产生伪 transition。
- 分开活跃 mask、loss mask、可用动作 mask、bootstrap mask；死亡个体与团队 terminal 不等价。
- `terminated`、`truncated` 和 final observation 按每个 agent 保存；终止后的占位动作不算真实行动。
- 重生或 ID 复用时明确是否为新个体；hidden、trace、优化器、共享参数分别 reset/保留。不能把上一局或另一队的状态意外接给新身份。
- 评价不更新训练 buffer/统计；连续适应评价若允许学习，就单独命名并计量。

环境 API 测试通过只确认部分接口，不证明学习目标或团队收益正确。[SMACv2](https://arxiv.org/abs/2212.07489) 进一步强调场景随机性和部分可见性；旧固定场景胜率不能代替新场景泛化。

可审计的原始事件至少包含 `team_run_id`、`env_instance`、世界/周期时钟、`agent_id`、角色、行为策略版本、局部观察身份、动作、即时与累计 reward 的明确口径、活跃/终止/截断标志、learner 更新序号。队友池记录来源团队、训练成本、checkpoint 哈希和采样概率。训练中已有中央状态可以另存，但应标作 critic/diagnostic 权限；不能把这份全信息日志当部署输入。

两个有判别力的检查是：给定 actor 的合法输入与随机状态，改变隔离的中央诊断状态不应改变动作；向两只共享参数的 agent 交换字典遍历顺序，不应交换它们的 hidden 身份。前者检查部署通路，后者检查身份对齐；任务真的对角色敏感时，不要求角色置换后回报不变。

扩大 agent 数时，还需检查 loss 是对活跃 agent 求和还是取平均，优势归一化是每 agent、每队还是整个 batch。相同联合步数下更多 agent 会提供更多训练样本；共享参数的梯度规模与有效 batch 也会改变。分别报告等联合交互、等 agent 样本与等总计算面板，不把一个口径下的收益写成所有口径都更高效。若用最佳 checkpoint，必须预先定义独立选择集并计入全部评价成本；最后 checkpoint、学习曲线面积和最佳选择后策略回答不同问题。

## 4. 三种“信用”分开设计

[项目模式](project-patterns.md)中的元控制信用是“这次修改学习程序，对未来回报有何作用”；网络模块信用是“信息、记忆、共享和梯度如何到达子部分”；团队信用是“联合回报如何用于各行动者的学习”。它们相关，但不是一个问题。

例如 [COMA](https://arxiv.org/abs/1705.08926) 的反事实动作基线不能直接证明模块路由有效；注意力权重不等于 agent 因果贡献；VDN 的效用分解也不是唯一真实贡献。元步长再加到 MAPPO 上时，先保持 actor/critic 权限与目标不变，比较固定率和元率；再做网络模块的单因素控制。一步方向可达性、当前修改价值、跨队友长期收益分别验收。

记忆还要分开：世界状态估计、队友行为估计、临时协作约定、以前队友知识。换队友后旧记忆可能帮助，也可能误导。普通 GRU、同大小 EMA、清记忆、仅清队友估计、完整持续状态是不同干预；只有环境确实提供换人信号时，算法才可直接据此 reset。研究者知道换人时点，并不意味着 agent 知道。

## 5. Self-play 与 cross-play 回答不同问题

Self-play 可能形成只与自己兼容的约定。保存独立训练人口的完整 cross-play 矩阵，锁定角色交换、队友采样权重与评价 episode 种子；另设未见训练种子、不同算法、不同技能或新行为规则的队友池。[Other-Play](https://proceedings.mlr.press/v119/hu20a.html) 是零样本协作的代表来源，不能由同队胜率推断这类能力。

对手池的每个 snapshot 都要有版本和取样概率。比较两法时采用相同**外部冻结评价池**；自博弈训练池可以随方法改变，但其生成预算与调度是方法成本。额外使用强对手、教师或搜索生成的行为应登记来源。固定一组旧对手的胜率上升可能来自利用其弱点，不能单独表述为普遍进步。

合作场景报告团队回报/成功率、cross-play 均值和尾部，必要时报告个体分配；二人零和场景报告对固定对手池的结果，并在可计算且有明确 best-response 求解器时测 exploitability；一般和博弈应明确福利、公平或激励指标。近似 best response 只给出有限求解预算下发现的可利用性，未找到漏洞不能证明 Nash。多方学习还可能循环，某一时点排名不等于收敛。

## 6. 持续多智能体：变化来自哪里

把外生任务/动力学变化、队友更换、队友继续学习、竞争者适应分开。固定队友快照的换人实验可控制变化原因；全员同时学习产生内生非平稳性，不能把同一 seed 解释为同一事后轨迹。

持续条件同时记录适应期损失、预定窗口恢复、旧队友回访、遇到新队友的学习速度和完整生命期回报。冻结 focal 参数而允许记忆更新，能检验快速状态适应；允许梯度更新则检验另一制度。回访时先做隔离的冻结读出，再按协议测再学习，区分保留与重新获得。不得在同一测试队友流后半段挑超参并回报全生命期成绩。

## 7. 一个分阶段、可否证的联合设计

[机器可读设计卡](../examples/designs/marl-crossplay.json)建议先在小合作任务做接口与可学性，再迁移到外部基准。第一阶段比较完整 IPPO/MAPPO；第二阶段固定已选训练制度，做 **普通 GRU/候选记忆结构 × 固定队友/隐藏更换队友**，分别保留总参数与总计算控制。第三阶段才加入元控制，与结构组成独立因子。人数、角色权限、reward、联合交互终点、对手生成预算相同。

升级条件：合法信息路径通过，强普通基线可学，候选在独立团队人口和预定新队友池达到预定有意义效应且旧队友非劣。停止或改写解释：仅赢小网络则不归因结构；仅在自博弈有效则不称通用协作；换队后只靠隐藏 ID 重置则不称无信号适应；团队回报改善但代价超预算则不能称同成本提升。主比较与效应阈值必须在实际训练前确定；设计卡中的规模不是统计功效保证。

若加入规划、options 或消息传递，另记录 option 终止、每 agent 的模型 rollout 数、通信轮数/字节/延迟和被允许共享的信息。中央 planner 统一代做决策不是分散执行的免费加速；学得 option 与手工子目标也有不同的开发信息成本。对应拆分见[预测与时间抽象](prediction-abstraction-options.md)及[规划与架构](planning-and-architecture.md)。

## 8. 接入现有执行流程

把设计卡落实成普通 `track: deep` 或 `continual` 的**外部协议**，在问题/配置中声明 MARL。将 `budget.steps` 明确约定为一项统一的联合转移计数；per-agent、vector-env、对手生成、模型查询和通信成本保存在配置与原始日志，现有导入器不自动理解这些时钟。一个 job 对应一个独立训练团队/人口；不要为同队每个 agent 建立伪独立 job。

执行 `freeze --external` 后，输入目录须恰好包含所有锁定 `job_id` 子目录。每个包含 `result.json`（job/lock 身份、完成或失败、有限主指标、真实训练与评价计数）、`producer.json`（源码版本、依赖锁、确切命令）及原始证据。其中 `diagnostics.evaluation_episodes` 必须等于注册数，评价交互足够且不超上限；其余字段遵循[外部合同](external-adapters.md)，导入成功不证明 MARL 实现正确。交叉矩阵、个体事件、队友池与原始 reward 另存为原始 artifact；不要把多维矩阵硬塞成未经定义的一个均值。

本文的方法介绍归于所链接的原论文/API；控制矩阵、状态拆分和停止规则是本工作台综合的**设计建议**。目录收录及设计文件均不表示已完成相应集成、benchmark 或新算法验证。
