## 每个模块都应回答的五个问题

下表是架构讨论与 agent 研究卡的共同骨架。接口名描述职责，不要求照搬一种固定神经网络。

| 职责 | 合法输入 | 可测目标/输出 | 主要时钟与持久状态 | 必要比较与证据 |
|---|---|---|---|---|
| 预测 / GVF | 指定目标策略下可估计的经验；声明离策略校正 | cumulant、continuation 所定义的未来量 | 每转移或每预测更新；参数/trace | 精确小问题、校准、目标策略覆盖；预测改善与控制增益分开 |
| 状态/表示抽象 | 当前观察、声明的历史或记忆 | 对预测、决策或模型有用的压缩 | 编码每步，参数按学习时钟 | 同信息/容量控制；状态混叠反例和新任务迁移 |
| 子目标 / option | 合法状态估计与可达目标 | initiation、内部策略、termination及其实际结果 | 原始动作时钟 + option 决策时钟 | primitive 强基线、固定技能、学习技能；累计时长与奖励 |
| 模型 / 规划 | 学得模型或已声明已知模型 | 候选行动后果与计划 | 每决策的 rollout/搜索次数 | 模型误差与行动收益；等交互、等计算和 oracle 权限 |
| 持久记忆 | 有来源和时间戳的新经验 | 新关联保存、寻址与后续行为使用 | 跨步状态写入、衰减和 reset | 无记忆、短历史、普通 RNN；存储/提取/再学习分别检验 |
| 内部通信/计算 | 当前合法编码与可读记忆 | 关系整合或工作状态收敛 | 每动作内部轮数；临时工作状态 | 浅头、等计算深头、固定消息、学习消息 |
| 学习控制 | 当下可用的学习状态与反馈 | 更新方向/尺度/时机对未来目标的作用 | 基础更新、元更新、信用延迟 | 原完整算法、固定规则、同基座干预；实际写入与长期收益 |
| 团队协调 | 分散 actor 的本地历史/合法消息；集中 critic 的声明权限 | 团队或各方效用、协作与竞争行为 | 联合世界、agent 动作、各学习器时钟 | IPPO/MAPPO 等强基线；角色、队友人口、cross-play 与资源 |

“更准预测”“更好抽象”“更多内部计算”“更稳定模块”“更高团队分数”之间没有免费的因果跳步。模块代理目标必须通过干预连接到整体原始目标；测试时不能用研究者知道的子目标、任务边界、队友身份或准确模型掩盖这个缺口。

## 两条贯通的研究路线

**学习控制路线：** 基础写入 → 可表达的控制器 → 合法信用估计 → 当前修改价值 → 独立闭环收益。将 GVF 作为辅助预测或元状态时，要分别检验预测质量、增量信息和控制器能否使用；把 option 或 planner 加入后，重新定义信用时钟与全部计算成本。

**表示与架构路线：** 信息是否足够 → 当前编码 → 跨步记忆 → 动作内计算 → 模块通信 → 持续维护。将它迁移到多智能体时，再分开 actor 间通信与单个网络内部通信、队友建模与世界建模、团队信用与模块/元控制信用。每一步先有更简单的强控制，不能一次改动所有模块后把增益归给某个概念。

## 使用等级与后续扩展

当前原生小例子覆盖 bandit、表格控制，以及单独依赖的 PPO–CartPole 适配。新增 GVF/options/规划/多智能体章节和设计卡用于**研究设计**；是否有对应可运行实现应查目录与实际 engine，不能从文档标题推断支持。所有设计卡在补齐版本、参数、权限、预算与适配验证之前均不得作为正式运行协议。

人类负责确定问题、效应与成本是否有意义；agent 可按研究卡提出实现、完成指定检查、保存完整证据并给出下一轮建议。无论谁提出改动，都经过同一条链：**设计 → 资格检查 → 冻结 → 完整执行 → 审计 → 分析 → 保留/修订/停止 → 新版本**。只有明确的科学证据支持升级结论，代码和文档数量不决定升级。
