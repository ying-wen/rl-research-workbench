# 规划、GVF、options 与完整架构：怎样设计可累积的实验

**状态：设计手册与结构检查工具；本仓库尚未实现下列规划、GVF、option或多模块学习架构。** [`catalog/modules.json`](../catalog/modules.json) 的10类模块全部是 `reference_only`，不能通过给模块取论文名称来得到一个可执行基线。本文的实验矩阵与验收门是建议，不是原论文已经验证的统一架构。

## 1. 研究单位从单个更新扩展到一个真实学习程序

一个完整 agent 可以包含表示、记忆、预测知识、世界模型、技能、子目标、规划、学习控制与协调。模块多不构成科学增量。每项设计首先回答：它掌握什么合法信息，优化哪个量，何时更新，改变哪一个后续决策，保留什么状态，使用多少数据和计算，怎样被反证？

Dyna把真实经验、模型学习和模型产生的学习更新组织到一起；MuZero在决策中使用学习模型搜索；Dreamer通过模型中的想象训练策略。三者的计算位置和数据制度不同，不能用一个“增加planning steps”开关互相冒充。规划也不必都发生在动作前。[Dyna](https://doi.org/10.1145/122344.122377) · [MuZero](https://arxiv.org/abs/1911.08265) · [DreamerV3](https://www.nature.com/articles/s41586-025-08744-2)

完整目标仍是预注册的外部回报与失败／成本约束。模型误差、GVF准确度、技能成功率、搜索估值或模块健康度都是分层证据；下游收益必须独立测量。

## 2. 统一模块合同

[`templates/module-contract.json`](../templates/module-contract.json) 给出一个**不可执行的结构示例**：记忆→模型→规划→actor，以及隔离的oracle诊断分支。合同可嵌入完整实验协议的 `modules` 字段。

| 合同字段 | 人类与 agent 必须说明的内容 |
|---|---|
| `id / role` | 模块身份与责任，不能只写一个算法名 |
| `inputs` | 名称、来源、可用事件、`agent`或`diagnostic`权限 |
| `outputs / downstream_consumers` | 实际产出与消费它的模块；训练中影响未来动作也算消费 |
| `persistent_state` | 参数、优化器、trace、记忆、模型、树、技能状态、数据库及其重置规则 |
| `update_clock` | 更新发生在哪个真实／学习／模拟／option事件，何时可以读取 |
| `objective / measure` | 模块的优化目标、可观察测量及与整体目标的连接 |
| `costs` | 数据、计算、时延、内存和跨时间增长 |
| `deployment` | 是否影响当前或未来真实行动，包括通过后续学习产生的影响 |
| `evidence_status` | proposed／implemented／validated；只是声明，不是检查器给出的认证 |

输入来源写为 `external:observation` 或 `module_id.output_name`。支持的 `available_at` 是 `decision_time`、`after_transition`、`after_update`、`previous_step`、`previous_option`、`previous_lifetime`、`initialization`。前一step/option/lifetime边允许真实延迟循环；同一周期的纯依赖循环需要更细的调度或改图，不能以递归调用默认解决。

```python
from rlworkbench.contracts import validate_modules
errors = validate_modules(protocol)
assert not errors, errors
```

检查器验证字段、唯一身份、双向引用一致性、显式延迟和声明的权限路径。任何诊断输入会保守地污染该模块全部输出，并沿下游传播；不能经中间模型、缓存或“上一生命期”洗成合法控制输入。actor 必须标记 deployment=true；实际影响策略的学习器也应标为true。

**这是声明的结构检查，不是因果证明或运行时信息隔离认证。** 它无法发现未声明的全局变量、文件读取、隐藏oracle、错误时钟、训练梯度侧信道或虚假的 validated 标签。部署资格仍需真实事件trace、接口审计、依赖闭包和干预测试。合法的集中训练信息也不能伪装成diagnostic后例外放行：应在相应任务制度中明示授权信息源、接收模块与训练／部署边界。

## 3. GVF：先定义预测问题，再检验知识是否被使用

一个GVF至少指定 cumulant、目标策略、状态／历史依赖的continuation（含终止）、条件输入和行为数据制度。形式上预测的是未来cumulant按continuation乘积累积的期望；换目标策略、cumulant或终止条件就是换问题。多预测并行学习的经典来源是 [Horde](https://aamas.csc.liv.ac.uk/Proceedings/aamas2011/papers/A6_R70.pdf)。

实验分三层：

1. **预测资格。** 用可解析小环境核目标与终止；测因果的held-out回报／预测误差、校准、时间尺度及off-policy支持。不能用未来标签改变当前输入，也不能只报TD残差。
2. **变化跟踪。** 分开环境改变、行为策略改变、GVF目标改变；记录目标版本，否则误差变化混合了三种原因。保留静态与重复情境检查。
3. **控制用途。** 固定下游容量，比较不用GVF、随机/固定特征、同容量无预测辅助、冻结GVF、在线GVF；给同样可用信息和更新成本。预测更准确但控制不改善，应保留这个结论。

GVF可作为表示、子目标可达性、option模型或规划启发；同一预测同时承担多种职责时，分别记录消费者与目标冲突。共享骨干的auxiliary loss也会改变actor，不能称“只增加一个只读预测”。

## 4. Options、子目标与抽象：把时间、信息和奖励说清楚

Option明确 initiation set、intra-option policy、termination，以及中断和执行失败语义。跨k个原始转移的SMDP目标需要累积这k步奖励和对应折扣乘积；不能把持续k步的option计为一个免费环境样本。经典框架见 [Sutton、Precup、Singh](https://doi.org/10.1016/S0004-3702(99)00052-1)。

预定对照包括 primitive-only、固定随机技能、手工技能的特权诊断、学习技能、冻结技能与在线更新技能。技能数量、总参数、累计训练数据、决策次数和执行时延分别匹配或公开。层级policy更慢的决策频率本身可能产生平滑效果，应加入等动作保持时间的非层级对照。

子目标必须说明坐标／潜变量语义、产生方式、可达性判断、内部奖励、低层目标与外部任务的关系。环境隐状态中的“门”“关键物体”标签若不是原生观察，不可免费给学习方法。Hindsight relabeling属于额外训练构造；共享数据和低层policy变化会使高层旧经验失配，需明确处理，而不是只报告子目标成功率。[HIRO](https://papers.nips.cc/paper/7591-data-efficient-hierarchical-reinforcement-learning.pdf)

抽象评价不仅测压缩率或聚类。构造当前抽象相同、但动作价值／终止／可达性不同的状态，测aliasing是否损害决策；测在已见与新policy、回访和新任务上的可用性。抽象可能只对指定价值函数和策略集合足够，不是“保留全部世界”。

## 5. 规划实验：数据预算与计算预算必须同时出现

### 最小的可解释矩阵

| 模型来源 | 不增加规划 | 有规划／想象 |
|---|---|---|
| 固定学习模型 | 相同表示、只读预测或固定策略 | 隔离推理/模拟计算增量 |
| 在线学习模型 | 保留模型学习及参数成本 | 检验模型适应与规划的交互 |
| 完美模型／模拟器oracle | 机会诊断 | 检查任务是否有可利用规划机会，明确特权 |

另列同交互、同数据的model-free强基线，以及计算预算相近的学习／策略基线。完美模型并非自动提供真实最优回报上界：搜索有限、启发有偏、策略受限时，它只是特权对照。若测试目标是“同样数据下规划收益”，保持真实交互一致；若目标是“同样部署时间的收益”，需要另一个固定墙钟／时延制度。不能用同样环境步数掩盖上百倍模型调用。

每真实行动记录：真实转移数、模型训练样本/更新数、模拟转移数、搜索节点数、扩展深度、候选数、策略／价值查询数、wall time、峰值内存与可重复硬件条件。模拟调用不会增加真实数据样本数，但要计入算力。预训练模型、外部数据和模拟器访问均有独立来源账本。

规划期间固定模型快照，或显式规定并发更新的版本一致性；不要让一次搜索树的不同边偷偷使用不同model版本。搜索深度和预算策略在开发集决定，不能看测试成功与否后无限增加算力。若超出deadline，记录fallback行为及损失。

### 模型质量与规划质量分开诊断

测一步预测、多步rollout误差、reward/continuation错误、policy排序和value误差，并检查模型访问分布与真实policy访问分布。误差不一定按重建像素大小决定控制损失：价值等价原则关注指定策略与函数集合下的Bellman更新一致性，但并不保证对未来所有任务和policy足够。[Value Equivalence](https://proceedings.neurips.cc/paper/2020/file/3bb585ea00014b0e3ebe4c6dd165a358-Paper.pdf)

加入相同快照上的计划与实际执行对照，定位模型被利用产生的虚假高价值；预定短／中／长rollout扫描以及固定／在线模型对比。滚动搜索更深但收益下降可能是模型误差、价值误差或搜索分配问题，不能直接断言“规划无用”。理想模型有效而学习模型无效，先查模型；理想模型也无效，检查机会、目标、预算和planner实现。

MuZero的原生搜索、Dreamer的想象训练和Dyna式模拟更新需要各自资格；不提供一个残缺替代实现却冠原算法名。完整作者方法面板与同基座机制面板并列，和两个持续RL项目中的强基线原则一致。

## 6. 完整架构实验：模块健康、机制归因与整体收益三层验收

先画有时钟的输入/输出与状态图，列出依赖版本、初始化、reset、替换和失效传播。模块A改善自己的loss可能让模块B的输入分布恶化；共同训练后的模块不是可任意交换的独立积木。

**关模块的诊断**回答当前已训练系统在多大程度依赖它；突然归零可能破坏输入分布，不能直接证明模块训练价值。**重新训练的匹配对照**才回答在没有该模块时一个适应后的系统能做多好。两者都可做，但名称与结论不同。替换时保留协议维度、合法信息、实际可训练容量及资源账本；padding零列不等于活跃容量。

对两个模块A/B先做2×2：都无、仅A、仅B、A+B。交互为 `J_AB - J_A - J_B + J_0`，独立生命期上估计；不能因为正均值就自动归因协同。模块多时先按依赖分层筛选或使用预注册的有限因子设计，再对关键交互补充确认，避免一次铺满所有结构、规划深度、元率和技能数。

验收层级分别是：接口/数值资格；可被干预支持的机制；完整新生命期上的回报、失败与成本。健康日志应包含NaN、梯度、写入、模型版本、知识目标漂移和技能终止，但这些不会替代最后一层。

## 7. 持续学习中的状态、快照与评估

至少区分六个时钟：真实环境行动、学习更新、option边界、内部模拟、外部通信与墙钟。一次内部计算不触发新的观察到达；option结束不自动等于环境episode结束；episode结束也不自动允许重置世界模型、知识库或元学习状态。哪些状态跨哪些边界持续存在必须写进合同。

原子快照包括参数、优化器、所有trace、归一化、RNG、记忆、GVF目标版本、option执行状态、模型、replay、搜索树及调度队列。一个只存policy权重的checkpoint不能恢复整个持续学习程序。恢复测试比较后续事件序列与原始轨迹；异步架构还需版本/因果顺序与可复现限制。

主指标仍来自不断学习的真实生命期。冻结评估使用隔离的完整快照与独立环境，不能改变在线模型、经验库、统计或partner；可额外安排有预算的在线适应评估，但必须另列制度。不要把“测试期可更新”与“看完测试未来再选模型”混为一谈。

## 8. 多智能体、协调模块与长期能力增长

区分环境中的多个行动者、agent内部的多个学习模块，以及工程执行中的多个worker。它们不是同一种MARL。环境多agent需要写各自观察/动作权限、合作或竞争奖励、通信带宽/延迟、共享参数/内存、集中训练信息与分散执行接口。一个联合训练人口／生命期才通常是独立随机单位，不能把其中每个agent当独立seed。[MADDPG](https://proceedings.neurips.cc/paper/2017/hash/68a9750337a418a86fe06c1991a1d64c-Abstract.html)

至少保留无通信、等通信随机/固定消息、参数共享与不共享、集中信息诊断、固定partner与新partner对照。planner若读取其他agent未来动作或全局状态，必须确认这是正式信息权限。异步事件、延迟更新、陈旧policy版本和故障恢复由执行协议单独记录；吞吐提高不等于联合样本效率提高。

长期能力增长要求跨阶段保留了可测、可用的预测/技能/模型/策略知识。分别检验同情境回访、新组合迁移和真正新任务；区分保留、快速重学、增加推理预算、外部harness调优与持久学习。把模块数量、技能库大小或知识库容量随时间增长一并报告；若额外容量解释收益，不能称为同资源持续适应。

## 9. 接回两个项目的下一步

StreamRate首先把GVF、critic、actor目标和学习控制分开登记：新预测是否提供合法、可校准的控制信息；控制器能改哪些算子；延迟信用何时被用于真实写入。规划器和更多记忆不能自动修复目标/评价错误，也不能在未完成强基线与当前根诊断时替代主问题。

表示项目按既有阶段推进：便宜编码→跨步记忆与步内计算→共享→拓扑。GVF可构成明确辅助目标，option/subgoal可提供长期控制任务，world model/planner可作为真实下游消费者；每次新增一种职责都需要新合同、资源和对照。先接一个小而可诊断的消费者，避免直接把全部机制拼成大架构再寻找解释。

交付时同时给出：完整协议、模块图/时钟、独立运行人口、资格结果、模块机制证据、全架构效能、成本、失败、负结果、未实现缺口及下一轮可反证问题。一个新的架构版本只有明确继承了哪些证据、改变了哪些假设，才能支持持续算法迭代。
