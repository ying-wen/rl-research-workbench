# 从研究手册到可用的实验工作台

工作台的价值应由一个使用问题判断：研究者能否把一个具体算法改动，变成可检查的实验和下一步决定？文献条目数、命令数和测试数都不能直接回答这个问题。

## 当前可以完成的闭环

| 使用场景 | 当前可做 | 仍需使用者完成 |
|---|---|---|
| 学习研究流程 | 原生 CliffGrid 与 bandit；计划、锁定、运行、审计、报告、配对比较 | 研究问题与有效对照的科学判断 |
| 检查神经训练接入 | 可选 SB3 PPO / CartPole 短程运行 | 完整调参、多个任务、足够运行与跨版本兼容检查 |
| 保存已有项目的结果 | 外部计划与完整人口结果导入规范 | 为真实日志编写并验证 producer；保留原始证据 |
| 设计 GVF、options、规划或多智能体 | 模块合同、信息权限、消融与测量建议 | 算法实现、环境适配、运行时隔离和系统实验 |

阅读入口与可执行入口应始终成对出现。每新增一种能力，应回答：哪条命令能运行，使用何种环境，在哪些测试中通过，还有什么不能推断。

## 建设顺序

### P0：让三种典型用户各完成一次真实任务

**任务 A：修正一个错误的 TD target。** 输入是一条短轨迹和两个实现。产物应包含失败的数值断言、修正后的更新、控制实验和报告。验收标准是错误确实被测试捕获，不是训练曲线看起来正常。

**任务 B：在同一 PPO 基座中测试一个改动。** 固定数据采集、观测处理和优化器。分别记录环境步、梯度步、参数量、时间与随机来源。先检查实际更新的梯度，再用独立开发运行选配置。当前可选 PPO 通路是起点，不是已完成这套因果比较。

**任务 C：比较变化后的持续适应。** 先跑静态保持、隐藏变化与旧规则回访。规定哪些状态跨变化保留。奖励按完整生命期累计。变化标签只用于离线诊断。bandit 已提供最小例子；深度持续控制仍需适配。

每个任务的公共交付包含：教程、最小配置、失败示例、测试、端到端命令和一份可重算报告。首次使用者应能在不阅读全部手册的情况下完成任务。

### P1：把一个教学实现接入正式记录协议

优先用 [教程仓库](https://github.com/ying-wen/continual-rl-tutorial) 中的可解析方法试接接口。先选择一个预测问题和一个控制问题。不要默认所有教学脚本都满足工作台的 agent 或 environment 合同。

接入前固定以下边界：

- `agent_state` 包含哪些参数、迹、优化器状态、归一化状态及随机数状态。
- `start/step/reset` 各自在什么事件发生。环境 reset 与学习器 reset 分开。
- 真实终止、时间截断、最终观测与 continuing bootstrap 如何编码。
- 结果生产者如何保留所有预定作业，包括失败、重跑关系与资源消耗。
- 恢复是逐位重现、统计重现，还是只能重启。不能统一标成“支持 checkpoint”。

验收要求：已知真值或参考更新通过；中断与恢复符合声明；导出的逐步奖励和聚合指标一致；故意损坏的回执被拒绝；运行可从新目录重做。完成后再将目录状态从 `reference_only` 提升。

### P2：从表格诊断扩展到共享参数

优先接入线性 TD、离策略预测反例和资格迹。它们连接 Sutton Part I 与 Part II，也能检验记录协议是否覆盖特征、行为概率和学习器状态。

随后选择 DQN 和 PPO 各一个固定小环境。DQN 检查 replay、target 与终止掩码。PPO 检查旧策略对数概率、优势估计、轨迹边界、优化轮数和 KL。固定数据更新对照与完整训练分别验收。SAC、TD3、递归策略和模型规划按实际项目需要接入，不直接宣称通用支持。

### P3：让研究比较覆盖选择过程和资源成本

现有配对比较按固定环境报告独立训练运行。下一层需要明确登记配置搜索、选择规则、开发预算、正式确认访问和每次失败。多环境聚合要预先定义任务人口与归一化。不能把不同奖励尺度的原始分数直接平均。

报告应同时展示主指标、失败率、交互、计算、内存与置信区间。保留逐环境结果。统计工具输出的显著性不能自动决定下一轮研究方向。

### P4：以明确接口接入持续学习模块

GVF 先检查 cumulant、continuation、目标策略和支持覆盖，再检查预测误差是否改善控制。Options 先检查启动、内部策略、终止、持续时间与 SMDP 目标，再检查规划或探索收益。模型与规划要同时记真实交互和想象计算。

每次先固定其余模块，比较新增模块、等资源基线及能推翻解释的消融。架构中的两个模块单独正确，并不保证它们耦合后稳定。完整智能体实验是独立验收层。

## 怎样接受一个新的后端

先用 [扩展指南](extension-guide.md) 填写支持矩阵。PR 应能展示“一个命令、一个实际配置、一个可复核产物”。同时附上至少一个应当失败的例子，如未知参数、动作空间不匹配、缺少最终观测或不完整结果人口。

长训练、集群调度和自动搜索需要项目预算与操作授权。它们不是完成公开发布之后自动开启的下一步。

## 教程与工作台的分工

教程维护问题定义、推导、手算、教学代码和练习。工作台维护研究协议、算法身份、运行状态、证据与决策。源码通过适配器复用，避免在两边维护没有同步约束的算法副本。先保证教学实现和实验合同能对应，再考虑统一 API。
