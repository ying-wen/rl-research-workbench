# 扩展一个算法、环境或研究项目

扩展应增加可检验的问题覆盖。先复用已有后端和记录协议，再增加确有必要的接口。目录中的 `planned` 或仅有来源条目不等于可以执行；只有实际实现、依赖、配置和测试通过的组合，才能声明相应支持程度。

## 新算法接入的最小交付

1. 建一个算法条目：原始论文、作者实现、版本/commit、许可证、完整方法还是同基座控制，哪些组件保留或更改。
2. 明确输入、动作与更新时序、状态、有效超参及默认值来源。拒绝或明确处理不认识的参数；不能配置里写了却被静默忽略。
3. 接入实验控制器规定的预算、随机性和记录协议。读取当前后端接口后实现，不另造一套无法合并的日志。
4. 添加手算或参考更新、边界条件和短轨迹测试。神经方法检查梯度流、目标网络、终止/截断、动作缩放；资源记录区分环境步与优化步。
5. 用最小完整运行产出所有计划作业的终态和失败记录，核对报告可以重算，再登记支持状态。性能实验留给独立研究协议。

可选后端需锁定依赖和真实版本，基础工具在未安装该依赖时应给清楚错误。若某算法只能运行特定动作空间，应在验证阶段拒绝不支持组合，而非让训练中途静默换方法。

## 新环境接入的最小交付

记录来源、原始版本、动作/观察/奖励、时间尺度、随机性、reset/终止/截断语义、许可证和外部资产要求。使用已知动作轨迹验证反馈，确认随机种子作用范围。适配后的步数、奖励变换或死亡语义如果改变原始问题，应建立有明确名称的变体。

task ID、完整状态、变化日程、最优策略和诊断标签分别列权限。环境控制器可以保存诊断字段，agent 只能收到协议允许的内容；在测试中用“添加诊断字段不改变 agent 输入”检查隔离。

若环境无法序列化，不宣称整段精确恢复；若只能有限 episode，不宣称原生无重置 continuous world。恢复和 continuing 包装都是研究语义，不能只当工程便利。

## 将一个现有项目迁入工作流

先写[项目章程](../templates/project-charter.md)，保留原项目算法、环境和历史证据的身份。通过适配器或导入分析接入，不为目录整齐搬动已有冻结来源。提取可复用内容：研究卡、运行合同、逐 run 原始数据、失败分类与分析脚本；不复制秘密、凭据或未经许可的外部源码。

按“数据可读→配置可验证→运行可重现→科学结果可复核”逐级标记。把历史已看过的数据登记为开发证据。不能因新工作流接受旧 CSV 就称已独立重现，也不能把两次分析同一运行计为两个样本。

## 人类和 agent 使用同一套资产

| 资产 | 人类用途 | agent 约束 |
|---|---|---|
| 项目章程 | 明确问题和资源边界 | 运行预算、可改范围、停止条件不能自行扩张 |
| 研究卡 | 审阅目标与反证 | 不完整时先补设计；不可跳到大规模搜索 |
| study/lock | 审核具体矩阵和版本 | 只按锁定身份执行；变更产生新版本 |
| 原始记录与失败账 | 复核总体与异常 | 禁止选择性删除、填造、改写或合并失败 |
| 决策与迭代日志 | 决定下一步 | 自动建议不等于科学晋级；无预算不自循环 |

agent 的交接固定提供文件、实际验证、结论范围和下一问题；计划与运行状态分开。针对有依赖的工作串行：先确定问题，再改协议，再冻结，再执行。读文献、审查公式和独立分析可并行，但同一文件与同一作业有唯一所有者。

## 何时值得扩展基础设施

只有出现重复痛点才增加能力：两个以上项目需要相同记录时抽取字段；手工错误反复发生时加验证；一个机制问题被接口阻断时增加后端。新 dashboard、调度器或自动优化循环都应明确它减少哪类错误，不以工程规模替代研究进展。

本仓库的本地命令不等于外部集群调度、完整 HPO 平台或统计自动裁决。接入这些系统仍须保持唯一作业身份、全尝试成本、重跑关系和独立确认。公开扩展时更新 README 支持矩阵、目录状态、最短运行说明和实际检查；只记录真正运行过的组合。
