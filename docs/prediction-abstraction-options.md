# GVF、抽象、子目标与 options：从模块有效到架构有效

本节把预测知识、技能和抽象视为可独立审查、又会相互影响的研究模块。先填写[模块卡](../templates/module-card.md)，再选择最小对照；不要一次加入预测、记忆、技能、规划，然后把收益全部归因于“架构”。[GVF–option 设计示例](../examples/designs/gvf-option-ablation.json)仅供设计与接入准备，**不是可运行的 workbench 协议，也未实现新算法后端**。

本节原论文链接于 2026-10-03 核验；下面的测试矩阵是本手册的综合建议，区别于论文原有实验或理论保证。

## 1. 固定模块合同和时间顺序

每个模块明确“问题定义”与“学习参数”的边界。改变 cumulant、目标策略、子目标含义或抽象映射，可能改变学习问题本身；这些变更需要版本和事件，不能只当参数更新忽略。

| 模块 | 合同与可测输出 | 不可替代的下游验证 |
|---|---|---|
| GVF | 给定策略、累积量与终止语义的未来预测 | 预测被用于决策后，是否改善原始任务收益 |
| 表征 | 从合法历史构造特征或 agent state | 混淆状态是否被区分，控制是否受益 |
| 抽象模型 | 抽象状态的奖励、转移或 option 结果模型 | 组合规划后的选择是否可靠且有收益 |
| 子目标 | 可达到的事件、集合或约束 | 技能能实现目标，目标对未来任务有用 |
| option | 启动条件、内部策略、终止条件 | 与 primitive 动作共同使用时的收益和成本 |
| 高层控制/规划 | 何时选技能、预测多远、计算多少 | 真实环境交互结果；不以模型内回报代替 |

逐步日志至少区分观测到达、预测输出、option 选择、primitive action、反馈、目标计算和参数更新。当前奖励可以训练此前预测，不能用来证明尚未发生的当前更新有益；选 option 的信息也不能来自该 option 完成后的状态。

## 2. GVF：先把“预测什么”定义准确

为每个问题登记 `q=(π,c,γ)` 和输入状态 `x_t=φ(h_t)`：π 是目标策略，c 是可从经验产生的 cumulant，γ 是 continuation/discount；特征 φ 属于实现与状态构造，不能自动假定它是 Markov。采用约定：

\[
G_t^q=\sum_{k=0}^{\infty}\left(\prod_{j=1}^{k}\gamma_{t+j}^q\right)c_{t+k+1}^q,
\qquad v^q(x)=\mathbb E_{\pi_q}[G_t^q\mid x_t=x].
\]

空乘积为 1。若问题另含终止 payoff，应显式登记，或说明如何并入 cumulant 与 continuation，不能漏掉也不能重复计入。c 可以是接触、能耗、传感器信号或其他合法经验量，未必是原任务奖励；一般 cumulant 的数值预测也未必是概率。[Horde（AAMAS 2011）](https://josephmodayil.com/papers/horde-final.pdf)提供多预测/控制问题并行学习的架构基础，[Multi-timescale Nexting](https://journals.sagepub.com/doi/abs/10.1177/1059712313511648)提供多时间尺度传感预测的实证背景。

**最小测试**：可解小系统核真值；γ=0 退化为下一 cumulant 预测；c=0 检查零目标；固定与状态依赖 γ 分别检查；一条手算轨迹核目标到达时点。记录尺度的物理单位和折扣约定；“长时域”不能仅由一个接近 1 的数字说明。

**离策略合同**：记录行为策略 μ 与目标 π、动作概率和版本。目标有支持而行为概率为零的区域，不能从现有数据识别；重要性权重和裁剪会改变方差/偏差。若 π 随学习变化，历史数据对应的问题版本和评价目标要明确。在线数据上很小的 TD 残差，不等于目标策略下预测准确。

**准确、校准与用途分开**：用独立目标策略 rollout、可解真值或满足假设的离策略评估检验预测；长期目标尚未到达时登记待评分，不用未来值训练当前决策。事件概率看可靠性和适当评分，连续预测看偏差、误差及条件残差。多尺度误差先考虑单位与目标方差，避免大幅值问题支配总分。最后保持下游容量与训练预算，比较不使用 GVF、固定随机特征、学习 GVF、冻结已学 GVF；只在下游原始收益改善后声称控制用途。

## 3. 预测问题也需要发现与筛选

人为选的 cumulant、policy 和时间尺度有先验信息，应给同等信息的对手。学习发现问题时，登记候选产生、分配更新、保留/删除和资源上限；发现成本计入整个算法。难预测不等于有用，误差高可能只是不可约噪声；容易预测的常数也不代表知识丰富。

先用固定问题库确认学习器，再比较固定人工库、随机匹配库和自发现库。匹配数量、目标尺度、策略覆盖及计算，检查下游需求变化后的复用。发现规则不能看未来任务答案；用开发任务确定规则，再在新任务和旧任务回访上测试。问题数量增长、互相关降低或覆盖更广属于诊断，主张仍要落到未来可测预测和控制收益。

## 4. Options：时间抽象改变更新对象

标准 option 记为 `o=(I_o,π_o,β_o)`：启动集合、内部策略和终止概率；另登记是否允许高层中断、执行期间哪些参数可更新。它执行 τ 个 primitive steps 后返回控制。在常数折扣下，一次 option 边界的目标为：

\[
Y=\sum_{k=0}^{\tau-1}\gamma^k r_{t+k+1}+\gamma^\tau V(x_{t+\tau}).
\]

对于逐转移 continuation，定义 `D_k=∏_{j=1}^k γ_(t+j)`，则 `Y=Σ_(k=0)^(τ−1) D_k r_(t+k+1)+D_τ V(x_(t+τ))`。不能统一只乘一次 γ，也不能用平均持续时间代替每次实际 τ。[Sutton、Precup、Singh（1999）](https://people.eecs.berkeley.edu/~russell/classes/cs294/f05/papers/sutton%2Bal-1999.pdf)建立 options 与 semi-MDP 的关系；[Option-Critic](https://ojs.aaai.org/index.php/AAAI/article/download/10916/10775)研究内部策略和终止条件的联合学习，并不要求额外人工子目标。

**三个边界分别编码**：option termination 让高层重新选择，通常仍 bootstrap；task termination 按任务目标结束回报；外部 truncation 是记录或运行限制，是否以及如何 bootstrap 取决于目标与可恢复状态。高层 rollout 被截断但 option 未终止时，应保留当前 option 身份并使用与算法一致的 continuation value，不把它伪装成正常 option 完成。检查 τ=1 退化、已知 τ 的手算回报、极短/极长 option 和同一步重选。

记录每个 option 的执行次数、持续时间分布、提前中断、终止地点、覆盖和成功率。只记高层步数会把长技能的交互成本隐藏；同时报告 primitive steps、模型步、规划结点和墙钟。

## 5. 子目标必须既可实现又有用途

子目标可以是状态集合、事件或预测变量阈值；给出判定器、成功时刻、初始状态分布、时限和失败代价。外观相近的状态未必可达；几何距离变近未必更接近控制目标。分别测试到达率、所需时间/成本、扰动后的可控性，再测试技能对新下游任务的价值。

后见经验中的实际未来状态可作为合法离策略重标记目标，但选择时间、标签来源及适配假设须记录；不能把只在未来才知道的最优子目标当作当时可用输入。诊断 oracle 可使用完整图或真值，必须独立命名并报告特权，不进入可部署方法排名。

至少比较 primitive only、固定手工 options、数量/持续时间匹配的随机 options、学习 options；在需要时加入目标匹配而仅策略学习不同的对照。保留 primitive fallback，检验错误子目标是否导致不可退出。不同 option 名称不等于不同技能：从动作分布、到达分布与成功集合检查行为重复、只选一个 option、全部 τ=1 或永不终止等退化。

[Machado、Bellemare、Bowling（2017）](https://proceedings.mlr.press/v70/machado17a.html)从表示的谱结构构造 eigenpurposes/eigenoptions；其探索与规划的区分提醒我们，同一技能不能因一类用途有效就被宣布普遍有效。

## 6. 学到表征不等于建立了有效抽象

特征映射 φ 可以服务价值近似；抽象模型还声称压缩状态下能预测奖励与转移。分别登记“表示学习”“状态聚合”“动作/option 抽象”“抽象模型”，不要用低重建误差、低秩或可视化簇代替 Markov 性、充分性或价值保持。

构造混淆反例：两个历史映射到同一抽象状态，却对同一动作产生不同奖励或未来抽象转移。检查这类差异是否可由历史/RNN 消除、是否会改变最优动作。在有限已知模型中可检验奖励和转移到各抽象块的一致性；这些 lumpability/bisimulation 类条件适用于相应定义，不能外推为任意神经表征的保证。近似抽象需说明度量、误差与任务分布；见 [Abel 等（2016）](https://proceedings.mlr.press/v48/abel16.html) 的限定误差分析，以及 [Abel 等（2020）](https://proceedings.mlr.press/v108/abel20a.html) 对状态抽象与 options 组合的条件。

实际消融分两层：固定表征只换抽象/规划，固定规划器只换表征；随后测试两者共同适应。跨任务迁移时保留会打破原合并规则的新奖励或动力学，检验抽象能否修订。一个训练任务上动作一致，不保证未见任务上的充分性。

## 7. 规划需要独立核算模型与搜索

为 option model 预测累计奖励、结束状态分布、持续时间或累计 continuation；随机持续时间下，不应简单把未折扣转移概率乘 `γ^(平均τ)`。在已知小系统验证模型组合，再测多段 option 组合误差。预测误差低但规划主动访问错误区域，是需要特别加入的反例。[Silver 与 Ciosek（2012）](https://arxiv.org/abs/1206.6473)提供 option model 组合规划的理论与算法背景。

匹配真实交互预算外，另报告模型训练、模拟步、搜索深度、展开结点、内存和决策延迟。规划收益比较无规划、等计算额外学习、primitive 模型规划和 option 模型规划；区分准确模型 oracle 与学习模型。测试更多搜索是否放大模型偏差；若是，修订模型或规划使用范围，而不是把模型内最佳分数当实际进展。

## 8. 架构实验与持续维护

先做预测 G 开/关 × options O 开/关的 2×2，固定高层控制器和原始奖励；分别观察预测准确、技能成功和总体回报。再在选定条件加入规划 P；三模块可承担时做 2³，否则预先选有理论理由的交互对照，承认未识别的高阶交互。每个有源模块有同容量/计算参照；固定模块消融与联合重调参的完整方法比较分别报告。

生命期包含静态习得、隐藏动力学变化、目标变化、感知变化、A→B→A 与新 C。记录 GVF 问题、option ID、抽象版本的出生、冻结、删除、替换和复用；ID 不静默复指另一技能。变化后将问题失效、估计器跟不上、技能失去可达性和高层误选分开诊断。持续扩库要有存储/计算上限，报告被遗忘知识的代价及重新学习成本。

每次资源再分配都有反事实对照：保留旧库、完全重建、简单固定容量淘汰、学习淘汰。只保留最后幸存技能会产生选择偏差；统计包含所有创建尝试、失败 option 和发现成本。相同目标复现时的快恢复和新目标首次学习同时报告，防止“记住旧答案”替代持续获取能力。

## 9. 接入两个研究主线

**学习控制/StreamRate 主线**：增加 GVF、高层 controller 或 option 后，列出每模块基础写入、率函数、元信用目标和更新时钟。先固定表征和 option 库，再只改变率控制；随后才研究库变化带来的元梯度/信用非平稳。option 持续 τ 步时，明确元信用按 primitive 还是 option 时钟衰减，并检验相同经验下的目标一致性。问题或参数重建后旧 trace 如何映射、截断或清理需要显式合同；清 trace 与清 learner 不同。局部更新有可计算信用仍需验证实际提交及完整生命期收益。

**表征/记忆主线**：将 GVF 作为预测目标、option 作为行为能力，而非让辅助损失天然证明特殊拓扑有效。先固定任务和预测库比较编码，再固定编码比较跨步记忆，接着加技能发现与抽象规划。匹配参数、持久状态、primitive 经验和推理预算；用无记忆、固定检索库、允许在线写入、参数学习开关分离知识来源。共享模块改进可能来自更多监督或计算，需对应控制。

扩展到多智能体时，每个预测/option 明确它条件于哪个对手或队友策略版本、哪些消息可见、是否使用集中训练信息。队友 option 的异步终止不等于环境 joint step；通信、等待和协调失败也计成本。独立训练单位是完整团队训练/生态轨迹，不把队员数当 seed 数。先用固定对手验证模块，再逐步放开共同学习，不将共享脚本成功误写成对新协作者泛化。

## 10. 每一级何时继续或停止

1. **规格门**：合法信息、目标、时钟、边界和资源齐全；不清楚就先不实现。
2. **计算门**：小系统真值、τ/γ/终止边界和状态恢复通过；失败先修实现。
3. **模块门**：独立预测准确或技能可达；不成立就修模块，不扩整体架构。
4. **用途门**：匹配对照中下游收益有支持；只有代理指标改善则收窄主张。
5. **长期门**：新 C 学习、旧 A 复用、变化适应与有限资源同时审查；失控时停止扩库。
6. **确认门**：锁定发现/学习/淘汰/规划的完整流程与开发规则，用新完整生命期确认；不逐模块挑各自最好时刻拼成一个不存在的系统。

## 11. 两套可以转为正式协议的配方

**配方 A：GVF 是否提供 option 所需的历史信息？** 构造一个可枚举走廊/门控环境：两个位置观察相同，但此前经过的标记决定哪扇门可通行；完整隐藏状态只给真值分析。先固定两种通行 options 与高层网络，比较当前观察、等维随机特征、合法历史/RNN、历史构造的 GVF 预测。GVF 问题预测指定策略下通行或碰撞的未来结果；保证行为覆盖并在小模型上核值。控制能力和信息输入分开：先判断预测是否区分混淆历史，再判断它是否改变 option 选择，最后比较原始收益。随后固定表征，只学习 option 策略；最后才做联合 2×2。如果 GVF 预测正确却高层不使用它，瓶颈在用途接口；若 RNN 同预算已解决而 GVF 未增益，就收窄为可解释预测模块，不能声称必要组件。

**配方 B：技能库是否帮助未来新规则？** 在可复现世界先形成固定容量技能库，再分别改变动力学、目标或感知。比较 primitive、冻结旧库、允许维护旧库、从头重建和容量匹配随机库。A→B→A 测复用，新 C 测获取，分别记录 option 可达率、终止错误、控制器选择与重学成本。所有方法共享变化生成规则和相同合法信息，但轨迹随动作而变化。若旧库访问更广却新 C 收益变差，要检查技能承诺时间和高层探索；若维护方法收益来自库无限增长，必须在相同存储上限下重新检验。将删除失败技能前的训练成本纳入全生命期，不只报告幸存者利用率。

两套配方都先做有限精确系统，再按需要接入复杂环境；任务更复杂时不把原来已知真值变成隐含免费输入。正式化时填写预算、各臂独立生命期、样本规划、失败代价、独立开发与确认分布。这里没有预设能保证成功的种子数或改善阈值；具体指标与停止条件由[研究卡](../templates/research-card.md)预注册。

完整运行仍需通过[统计协议](statistics.md)、[迭代流程](iteration.md)和[外部适配合同](external-adapters.md)。本节提供研究接口和实验配方，不声称这些架构已集成或效果已验证。
