# 算法修改之前，先写出会发生什么

研究对象是智能体在允许信息和资源下取得的收益。可以近似价值、导数和计算，不能悄悄将目标换成一个容易改善的代理损失。每项新增模块都需要一个明确目标、经验来源和会让我们删掉它的结果。

## 从症状到最小机制

把“不稳定”写成具体事件：值估计发散、更新后 KL 突增、训练间双峰、变化后恢复变慢或长期资源增长。至少提出两种解释，并设计能区分它们的实验。例如奖励后移导致回报下降，既可能是信用不足，也可能是探索从未获得反馈；单纯增加 trace 不能自动排除后者。

按此顺序写研究卡：原问题→目标函数→理想更新/约束→实际可得估计→近似和偏差→逐事件算法→可测预测。理论中使用的完整状态、漂移点、最优率和未知常数，应与 agent 可见输入分开；只给诊断 oracle 的信息不得进入候选方法。

## 每个模块的规格

| 项目 | 必须写出的内容 |
|---|---|
| 输入 | 观测、动作、奖励、历史或缓存；到达时间与权限 |
| 状态 | 参数、优化器、trace、归一化、记忆；创建与重置时点 |
| 目标 | 可估计的预测或控制目标，单位、反馈延迟和偏差 |
| 操作 | 基础更新、率或预条件、裁剪、归一化的先后次序 |
| 输出 | 实际写入哪些参数或动作；何时影响未来行为 |
| 反证 | 什么观察意味着无作用、作用相反或作用来自替代解释 |

actor、critic、表示与元学习模块的目标可能不同。critic 误差下降不保证策略改善；正有界步长不等于闭环稳定；元梯度非零不等于在线可学。将这些中间结论分别登记，再检验通向回报的链条。

## 比较到真正执行的参数和写入

不能只比较论文符号中的 α。实际更新可能含奖励缩放、优势归一化、梯度裁剪、Adam 状态、坐标倍率、更新频率与重复数据使用。报告有效配置及真实更新：名义步长、实际参数增量、增量相对参数尺度、actor KL，以及每交互步更新次数。不同算法可保留不同语义，但比较必须清楚。

对新优化或自适应模块，先考虑调好的常数步长、简单日程、降低更新幅度等廉价对手。等更新范数只隔离一个几何因素；不意味着策略 KL、方向、数据或长期行为相同。保持所有量相同通常不可能，应明确本实验控制了什么、牺牲了什么。

## 让消融具有判别力

两个改动 X、Y 使用基座、X、Y、X+Y 的 2×2 设计；在选定评价尺度上考察 `J_XY - J_X - J_Y + J_0` 及不确定性。若主张模块交互，只有“完整方法减一项”的比较往往不足。

根据机制选择额外对照：同容量模型控制表达力；固定或随机信号控制额外参数；错位信号检验信息对齐；幅度匹配控制更新大小；完整作者算法衡量实际竞争力。打乱会改变边际分布和时间相关性，应说清破坏的因素。oracle 只是有额外信息的诊断参照，除非证明了上界性质，不能叫理论上界。

## 三条轨道的设计顺序

**经典 RL**：先让可枚举系统给出真值；检查极端参数、更新顺序、探索覆盖和不满足假设的反例；再在闭环中检验样本效率与控制。有限 MDP 中正确并不意味着非线性近似中稳定。

**深度 RL**：先固定数据检测估计器和梯度，再放开行为回路；将网络、优化器、replay、目标网络和预处理视为算法的一部分。完整方法性能实验与同基座机制实验并列保存。

**持续 RL**：明确过去经验通过权重、记忆、缓存、搜索还是人工规则影响未来；设计学习开关和检索开关的交互对照。只增加任务内搜索或检索成功，不足以证明跨任务持久学习。需要在新未来任务上检验经验的增量价值，并计入存储、检索与更新成本。

到一个候选能够被最小实验明确否定时，就先运行该实验。未出现可测区别时，优先修订问题或诊断，不通过叠加模块让解释变复杂。
