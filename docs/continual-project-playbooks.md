# 两个项目的深度持续强化学习实践手册

**状态：新研究设计，尚未登记、尚未运行；两个外部训练适配器尚未实现。** 本文把“延迟回报控制学习率”和“网络表示／记忆／连接组织”转化为可逐阶段执行、被反证和扩展的研究程序。它不导入原项目旧结果，不复制受冻结保护的运行代码，不把旧队列改造成新实验。

机器可读起点：[`streamrate-development.json`](../protocols/streamrate-development.json) 与 [`representation-development.json`](../protocols/representation-development.json)。二者可以通过外部协议的结构验证，但 `input_adapter_ready:false`；`UNREGISTERED`、未分配种子及方法默认配置必须在适配器资格完成后替换，并生成新冻结版本。它们不是内置引擎可执行 profile，也不是已获批准的启动命令。

## 1. 共同研究对象：完整的学习生命期

每个独立种子生成一条完整学习生命期，主要终点为 `J = sum(raw_reward[0:T]) / T`。包括初期探索、每次隐含变化后的损失、回访、新阶段以及最后未完成 episode 的奖励；不只看尾窗或最好 checkpoint。episode、阶段、1000步窗口不是额外独立种子。

严格 streaming 的约束分别登记：历史经验是否保留、每个新转移做几次更新、推理内部迭代是否增加、辅助预测读什么信息、重置哪些状态。没有 replay 不自动证明持续适应；跨 episode 不重置参数也不自动证明长期学习。若增加 replay SAC/PPO 作参照，明确其制度与算力，不混称同一 streaming 比赛。

两个项目每轮都保留完整外部 **Stream-AC、Metatrace、Intentional-AC** 面板，同时保留共同基座机制面板。完整方法允许真实网络、归一化、信用和优化器不同；机制实验才把相关因素锁定。模块消融不代替完整外部算法。Metatrace vector/Mixed 的方程移植必须写明身份；Intentional-Q 不改名为 Intentional-AC；接口不支持时登记缺口并推进资格，不能悄悄删除。

### 共同变化日程

两份协议提出每条 `T=400148` 转移、四个各 `100037` 步阶段的 **A→B→A→C** 日程。变化发生于从零计数的奖励索引 `100037, 200074, 300111`，即第一条新阶段转移编号 `100038, 200075, 300112`。这使三个切换均不与200步 time-limit 重合。切换不额外 reset，不清参数、优化器、归一化、元信用或记忆；原生 episode 的真实边界按各算法事先约定处理。

日程只交给环境内核和隔离分析器，不进入策略输入、观察归一化、学习率特征、经验采样器或任务路由器。不同方法共享种子的外部日程与外部随机源规范，但动作改变访问分布，因此不能要求它们共享实际状态轨迹。诊断可以知道变化时刻；agent 必须从实际观察与奖励适应。

这是一组**新提出的诊断任务**，不是原论文 benchmark，也不冒充原计划的两目标交替环境。版本、任务可达性、奖励时钟及源代码仍须资格验证。

| 任务 | 改变的因素 | 对照与解释范围 |
|---|---|---|
| Pendulum 静态 | 不变 | 检查持续适应机制是否损害静态学习 |
| 隐藏重力 A-B-A-C | 提议 g=10、7.5、10、12.5；奖励定义不变 | 动力学改变与旧动力学回访，重力不直接给策略 |
| 隐藏目标 A-B-A-C | 提议目标角 −15°、+15°、−15°、0°；动力学不变 | 奖励后果改变与回访；目标角不直接给策略 |
| Reacher-v4 静态 | 保留原任务与观测 | 任务迁移及副作用检查，不只围绕 Pendulum 选赢家 |

目标切换的奖励为 `-wrap(theta-goal)^2 - 0.1*velocity^2 - 0.001*applied_action^2`。奖励时刻和实际受 clip 的动作须与所固定的 Pendulum 源码一致。固定 ±15° 的可保持性与学习可达性先分别检查；不能只凭公式可行就假定每个基座能学。给目标角的 oracle 只能检查机会／可达性，不进入 task-free 排名，其轨迹不用于正式训练。

**不能只测一次 shift。** 初始开发覆盖静态、A回访和新C；独立确认增加未用于选择的 dwell time／变化幅度、缓慢漂移、更多复发与更长生命期。另做任务顺序扰动检查年龄效应。记忆问题需专门的延迟 cue 条件，不能由物理变化任务自动推断。

## 2. 项目一：StreamRate——延迟经验怎样指导当前学习修改

### 2.1 先把三个模块的目标分开

critic 估计明确的价值对象；actor 根据明确改进目标改变策略；元层判断实际学习修改对后续继续学习回报的影响。TD误差降低、元梯度非零、率被提交、数值恒等式成立，分别只是局部证据。

当前正有界倍率写入可记为 `Δw_i = b_i * d_i`，其中 `d_i > 0`。它不能激活原来为零的 `b_i`、不能反转该坐标的符号，也受倍率范围限制。因此改变步长不一般等于改变 actor 的优势／精英投影目标，更不自动修复 critic 的评价偏差。允许条件倍率改变期望方向，但这与同次写入的可表达性是不同命题。

### 2.2 四个可分开失败的研究阶段

| 阶段 | 最小设计 | 主要反证／停止依据 |
|---|---|---|
| S0 忠实性与时序 | 作者调用链对齐；逐事件 trace；小问题有限差分／精确条件树；失败单步重放 | 方程移植或时钟不对，先修独占新适配器；不扩大训练 |
| S1 率与信用 | StreamRate、module-only、causal shifted-features、functional-fixed，同一基座 | 只有区间排除预定有意义增量时，才能作为局部信息收益不足的证据；区间宽则记精度不足，不能凭“元层工作了”升级 |
| S2 目标×率 | 共同 Q 评价基座上：优势 actor／精英 actor × 固定率／延迟元率 | 固定目标改变解释全部收益，则收益属于算子；元率增量另需证据 |
| S3 独立长程确认 | 完整外部面板、锁定配置、独立生命期、未见变化族 | 支持静态损害、长期退化或失败的证据如实保留；收益区间过宽时记效益未确立，不写成已证明无效 |

S2 是新 Q 基座适配，不能叫原 V-critic Stream-AC；无 replay 的 GreedyAC 移植不能冒称完整原作者 replay 方法。固定表示、Q、候选数、熵、观测和交互终点。记录参数写入、策略 KL、预测排序与实际回报；等参数范数不是等策略改变。

actor 和 critic 也要分开：使用准确评价仅限隔离诊断，帮助区分“目标没改进机会”与“近似评价错了”；真实 agent 仍只用合法流式估计。准确 Q、未来继续值、变化标志不能成为元控制免费输入。若目标在正倍率集合外，才考虑扩大可执行算子；若简单共同偏置已足够，则保留简单方法。

### 2.3 当前使用的元信用必须因果可审计

每次日志至少记录：行动前可用的元状态摘要、行为随机数流标识、动作和奖励到达时刻、基座原始写入、控制倍率、实际写入、元 credit 累积时刻、提交时刻和受影响的后续更新。明确“奖励在何时成为可用信息”，不能让当前动作或先前写入使用尚未到达的奖励。滞后信用在当前部署是否仍有价值，应通过新根／新阶段干预检查，不能只验证它解释了旧轨迹。

K、h、元步长是否固定单独登记；不要把学习步长称为学习更新频率。停梯度的参数日程、有限信用长度和近似 critic 都写入偏差清单。历史敏感度、普通资格迹和元资格迹承担不同职责，不能混用名称。

### 2.4 提议 pilot 与后续调参

`streamrate-development.json` 含8臂：4个完整外部配置（Stream-AC、Metatrace vector、Metatrace Mixed、Intentional-AC）和4个 StreamRate 共同基座规则；3任务×3拟议新种子×400148步，共 **72生命期、28,810,656环境步**。这是尚未执行的开发默认锚点面板，不是充分调参，也不是已有原矩阵的重跑。

Intentional 的 functional eta 不等同于 SGD 学习率。方法默认锚点之外，另立独立调参研究：每法相同明确搜索资源，各自合理的参数化；actor／critic rate 的独立网格与元率等特有维度记录成本。完整开发终点全部到齐后才选配置，不能按较快完成的前缀调参。

## 3. 项目二：表示、记忆、计算与连接——逐步增加复杂性

### 3.1 A阶段：先问便宜编码是否值得用

共同基座先保留原作者独立的 actor／critic 网络、预处理和学习规则，不同时加 StreamRate、辅助重建、预测损失或结构增长。

| 臂 | 唯一主变化 | 它排除不了什么 |
|---|---|---|
| 原 MLP | 原两层128宽网络及原算法 | 是能力锚点，不是容量匹配 |
| FTA | 最后隐藏层 LN 后的激活按选定作者版本替换 | 参数量、计算与梯度变化仍需分解 |
| 参数匹配 MLP | 调整真实可训练宽度；按参数差最小确定，不看回报选 | 参数相近不等于算力相同 |
| 固定随机特征 | `concat(x,0.5*tanh(Bx))`，216个额外固定特征 | 不提供可学习历史记忆，也不是同容量控制 |

选定2026 FTA版本须核实8 tiles加右移ReLU尾部等于每标量9个输出；不能把它误当同宽逐元素激活。actor／critic分别计算参数量；匹配误差公开。零输入填充不是活跃容量对照。固定随机特征的常值幅度与 EMA 比较需先校准，否则不能归因“记忆”。

`representation-development.json` 含上述4个表示配置与另3个完整外部配置（Metatrace vector/Mixed、Intentional-AC）；静态Pendulum、目标 A-B-A-C、静态Reacher，共 **63生命期、25,209,324环境步**。拟议种子未占用，不与旧开发种子合并。FTA若只胜原小MLP、不能胜参数控制，不能声称编码本身有增量。即使首批成功，也不能单独确证“局部稀疏性导致收益”。

### 3.2 B阶段：跨步记忆与动作前多轮计算分开

先设置延迟 cue 控制任务及完全可见版本：同一个当前观察在不同合法历史下要求不同动作。预定延迟长短与干扰；保留无记忆MLP、两帧输入、自连接状态、小门控RNN。遮蔽速度Pendulum只能提供短历史检查，不能代替这个判别。

固定同类跨步记忆 `m_t=U(m_(t-1),x_t)`，每个真实到达只推进一次。比较：K=1浅头；同一工作头共享参数K=4；等计算的四层非共享深头。三者具有相同观察、m直读旁路和跨步信用约定。动作前K轮不是K次环境转移，也不是K次TD更新；归一化、奖励处理和优化器不能被意外调用K次。

只胜浅头却不胜等计算深头，只支持额外计算。另用同一冻结快照改变K，检查现有模型如何使用计算；它不能代替各配置独立训练。架构相同的U经不同训练不会具有相同状态，应避免“相同历史表征”的过强措辞。

RNN敏感度 `S_t=A_t*S_(t-1)+G_t` 与普通资格迹是不同递推。若用 detach-GRU、截断BPTT或其他近似，明确历史路径缺失；不能作为完整历史信用的充分基线。完整敏感度也只针对声明的输入与参数日程，不等于整个闭环学习程序的全导数。

### 3.3 C阶段：选择性共享；D阶段：最后才检验生物拓扑

C阶段在固定容量和基座下比较 dense、self-only、随机稀疏、模块稀疏加跨模块边。任务应同时包含共同因素重组和相似线索的冲突后果，均含回访。匹配边数、度、输入和读出覆盖、符号与初始化尺度；不能顺便改变 LN 分组、优化器或损失。真实硬mask贯穿前向、梯度、资格迹和优化器槽，稀疏初始化不等于永久稀疏连接。

同时报告迁移、干扰和完整回报。干扰下降而迁移也丢失，只说明隔离增强；模块度升高不等于控制改善。通过这一步后，D阶段才将真实果蝇拓扑与度／符号／强度匹配重连及普通稀疏图比较。结构增长另开协议，拆开增边、累计容量和优化器重置的影响。参数、FLOPs、实测吞吐、内存与存储分别报告。

## 4. 统一诊断 API：恢复时间有明确的观察边界

[`continual_metrics.py`](../rlworkbench/continual_metrics.py) 提供标准库离线函数：

```python
from rlworkbench.continual_metrics import summarize
report = summarize(
    raw_rewards, [100037, 200074, 300111],
    window=1000, baseline_window=5000,
    tolerance=0.05, persistence=5,
    planned_steps=400148, end_reason="completed",
    same_reward_scale=True,
)
```

这些数值是开发建议，必须在看到结果前固定；0.05是原始奖励绝对单位容差，不是百分比。比较不同奖励尺度时不能照搬。阈值为切换前窗口均值减容差；每个恢复窗口全部位于切换之后、步幅1，连续5个合格窗口才确认。确认时间在最后窗口的**末端**，不会倒填到窗口开始。恢复阈值可能在新任务不可达，因此恢复速度不单独排名；同时展示切换后原始收益与任务机会诊断。

输出区分：`recovered`；完整预定阶段内未恢复的 `not_recovered`；行政提前停止的 `censored`；竞争失败 `crash`；尺度不可比 `not_comparable`；切换前同阶段基线不足 `insufficient_baseline`；变化尚未观测 `not_observed`。完整阶段仍未恢复时，其恢复时间在统计上仍是右删失；这不等于算法崩溃。崩溃前若已恢复，保留该事件，同时生命期仍标失败。

未完成生命期只给 observed-prefix mean；完整生命期 `mean_reward` 返回空值，避免把短前缀当完整收益。每阶段原始总奖励和样本数保留。窗口重叠不增加独立样本数；本工具不自动作生存分析、不假定非信息删失，也不把恢复时间当跨任务无条件可比的分数。

## 5. 让 human 与 agent 每轮都能执行相同决策

1. **写六项研究卡。** 原问题和反证；agent合法信息；actor/critic/meta目标；近似偏差；唯一主改动；最小实验和停止依据。
2. **登记能力缺口。** 外部代码来源、版本、许可证、接口、原方程移植身份、环境奖励时钟、reset和bootstrap。三强基线缺一就不能完整比较。
3. **做最小资格测试。** 源码同轨迹桥、小反例、数值导数、固定目标可学性、无标签泄漏、真实raw日志、失败注入和资源资格；通过不是效能。
4. **冻结新独占人口。** 预定算法×任务×配置×种子×终点；独立调参与确认生命期；保存协议和producer闭包hash；已有在跑队列不热加臂。
5. **完整运行再分析。** 所有失败、缺失、幸存者和完整结果分开。退出成功、内容通过、统计通过、科学主张通过分别记状态。
6. **一次只改一个主要解释。** 当前结果支持哪个机制、反证哪个机制、仍有哪些竞争解释；决定保留、修正或停止。新方向新版本，不在旧case上悄悄修复。
7. **独立确认。** 配置选择冻结后打开新生命期；任务族与时间尺度扩展；强基线、资源和失败完整。只有这一步的相应证据才支持推广措辞。

本轮协议内的 `minimum_effect=0.01`、failure floor −100及恢复容差都是显式待注册 pilot 占位口径。Pendulum与Reacher不能按未归一化原始分数跨任务平均排名，实际确认须预注册每任务的实际意义阈值及失败复合终点。失败floor是分析构造，不是补出来的环境奖励；必须同时报告失败率、失效时间／类型和幸存者描述。系统中断与数值失效分开，未知原因不写成已证实发散。
