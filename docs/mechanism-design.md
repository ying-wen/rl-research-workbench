# 从机制设计到完整学习程序

这份文档是[完整手册](handbook.md)与[代码对应表](handbook-code-map.md)之间的推导桥。它回答“为什么需要这个机制、机制能改变什么、什么实验能推翻解释”，再把结论落实到代码与工具。下文的统一记号与实验路线是工作台的综合设计建议；原论文依据保留在完整手册和专题文档中。这里没有提出适用于所有 RL 的收敛定理，也没有把工具校验解释为定理认证。

阅读顺序是：外部目标 → 合法历史与 agent state → 模块预测与动作 → 学习算子 → 信用与时钟 → 模型与规划 → 持久改变 → 完整生命期证据。任何一步缺失，后面的好曲线都可能回答了另一个问题。

## 1. 从外部目标推到模块目标

先指定环境族、信息制度、资源约束与评价分布，再选目标。例如持续控制可以在固定生命期 T 上定义

$$
J_T(\mathcal A)=\mathbb E_{\mathcal E,\xi}\left[\frac1T\sum_{t=0}^{T-1}R_{t+1}\right],
$$

其中 $\mathcal A$ 是包括初始化、探索、学习、记忆维护与部署计算的完整程序，$\xi$ 包含该程序的随机性。平均长期奖励极限、有限 T 的生命期均值、折扣回报、最后策略的冻结表现是不同对象；不能因实现方便互换。选定 T 也必须交代它是否足以覆盖所声称的延迟收益与长期退化。

接着问每个模块如何影响这个对象。critic 近似价值以改变 actor 更新；GVF 提供指定策略下的未来预测；记忆将历史压成行动可用状态；规划消耗计算改进选择。它们优化的平方误差、TD 残差、辅助损失或搜索值都不是 J。设计应明确一条可以逐段检查的链：**模块输入有信息 → 输出对目标有效 → 下游实际使用 → 行为改变 → 生命期收益改变**。任何中间环节都允许得到负结论。

反例：在访问频繁且与决策无关的状态上降低预测误差，可以改善总 MSE 而不改变一次动作。对应实验应检查决策相关条件下的误差及实际消费者，而非继续放大预测网络。目标与统计对象的来源见[目标定义](handbook.md#guide-objective)、[统计对象](handbook.md#stats-framework)。

## 2. Agent state 是合法历史的压缩，不是环境真状态的别名

记决策前可得历史为 $H_t$，持久程序状态为 $Z_t$，则

$$
X_t=f_{\theta_t}(H_t,Z_t),\quad A_t\sim\pi_{\theta_t}(\cdot\mid X_t),
\qquad Z_{t+1}=F(Z_t,O_{t+1},A_t,R_{t+1};\theta_t).
$$

此式是接口分解，并不保证 X 是 Markov，也不要求实现保存全部 H。参数、优化器、trace、归一化、循环记忆、知识库和模型均可能属于 Z；它们各自的写入规则必须声明。研究者知道的相位、未来目标和最优参数另设诊断通道。信息在上一阶段出现过，并不会自动从特权变为合法。

最小反例是两个历史产生相同当前观察，但要求相反动作。先验证纯观察方法确实受此限制，再比较合法历史、普通循环模型、候选记忆；否则“记忆收益”可能只是额外参数或不公平输入。做干预时保持合法输入与随机状态相同，只改变隔离的诊断字段，部署动作应不受影响。它检查已覆盖路径，不能证明所有隐藏读取不存在。

[`validate_modules`](../rlworkbench/contracts.py) 可检查声明的引用、权限传播和即时循环；[`ContractTests.test_diagnostic_taint_cannot_be_laundered_by_middle_module`](../tests/test_contracts.py) 与延迟循环测试提供反例模式。真实文件读取、共享张量、梯度与全局变量仍需实际代码审计。

## 3. 区分基础方向、更新几何和算子职责

把一次学习写入写成

$$
\Delta\theta_t=U(\theta_t,Z_t,D_t;\eta_t),\qquad
\theta_{t+1}=\theta_t+\Delta\theta_t.
$$

D 是当时合法数据，η 是控制量。需要分清：改变 TD/优势目标，改变基础方向 b，给方向施加率或预条件，裁剪最终写入，以及更改数据复用频率。相同名义学习率不代表相同算子；同更新范数也不代表相同方向、策略 KL 或行为分布。

例如 StreamRate 的某类正坐标倍率写入可表示为 $\Delta\theta_i=d_i b_i, d_i>0$。对同一次给定 b 的写入，它不能把零坐标激活，也不能反转该坐标符号；允许区间还限制幅度。这只描述瞬时可达集合。倍率依赖经验后可能改变期望方向，长期轨迹也会改变，因此不能由这个几何事实直接推出“调率无用”，或反过来声称它能替代任何 actor/critic 目标。

每项推导保留四层：**理想目标及假设 → 精确表达 → 可计算近似及遗漏项 → 实际调用与写入**。有限差分要对应同一函数、同一初态和随机条件；截断反向传播、stop-gradient、陈旧目标、重要性权重裁剪须记录。数值对齐支持局部实现一致，不证明估计无偏、长期收敛或控制收益。

经典参照可直接读 [`td_target`](../rlworkbench/engines.py)：Q-learning 的 max 与 Sarsa 的采样动作改变目标；真正终止关闭 bootstrap，外部截断保留它。[`EngineTests.test_external_time_limit_preserves_actual_observation_and_bootstrap`](../tests/test_engines.py) 检查这种边界。它是可迁移的测试模式，不是 StreamRate 元梯度测试。

## 4. 信用必须落在真正产生后果的事件上

至少区分观察到达、预测、行动、奖励、目标构造、参数写入、元更新和下次读取。一次奖励通常是过去行动及历史学习状态的后果，不能因为与当前写入同处一个循环就自动归因于当前写入。延迟信用的理论对象应说明：对哪个历史参数、哪个学习修改，保持什么固定，并允许哪些后续学习路径变化。

options 又引入另一时钟。持续 τ 个原始转移的动作抽象，其常折扣目标包含 $\sum_{k=0}^{\tau-1}\gamma^kR_{t+k+1}+\gamma^\tau V(X_{t+\tau})$。元信用、资格迹和更新频率按 primitive step 还是 option boundary 衰减，必须与目标一致。option 结束、task terminal、外部截断、记忆清理是四种事件，不能用一个 done 位代替全部语义。

先手算一条短轨迹，再比较逐事件日志；最后检查 checkpoint 恢复后的未来事件。反例覆盖 τ=1、长 option、同一步结束与重选、外部截断时 option 仍活跃、奖励到达时参数已换版本。当前仓库尚无原生 option 或元信用实现；[时间抽象专题](prediction-abstraction-options.md)给出合同与测试配方。

## 5. 从预测、抽象、子目标到规划，逐个检验接口

GVF 定义目标策略、cumulant 与 continuation，预测是否准确需要相应覆盖和评价制度。抽象则提出更强的压缩主张：哪些历史可以合并而不损害指定任务与策略集合下的决策？子目标还必须可达到、有用且能给出失败语义；option 将它变为可执行能力；模型描述动作或 option 的结果；规划消费模型与计算预算。

一个可重复的开发顺序是：可解小世界核 GVF 真值 → 构造抽象混淆反例 → 固定技能验证子目标可达 → 核 option 累计回报与时长 → 固定准确模型检查组合规划 → 换学习模型 → 最后允许模块共同适应。若完美模型有收益而学习模型没有，检查模型及其使用分布；若二者都没有，先检查规划机会、目标、预算和实现。完美模型加有限搜索也不是自动的最优值上界。

[`module-contract.json`](../templates/module-contract.json) 提供结构示例，[预测与 options](prediction-abstraction-options.md)、[规划与架构](planning-and-architecture.md)给出公式及对照。模块字段通过验证仅表示声明自洽；目前没有 GVF、option、子目标发现或规划训练后端。不要把 reference_only 条目注册成虚假的可运行能力。

## 6. 用有判别力的干预连接局部机制与整体收益

对机制 X、Y，先设共同基座的四格：0、X、Y、X+Y，在预定评价尺度估计 $I=J_{XY}-J_X-J_Y+J_0$ 及不确定性。正均值不是协同的充分证据；交互大小依赖尺度、任务和调参制度。固定超参删组件与各版本重新调参，分别估计组件依赖和方法族能力，不能混写。

| 主张 | 最小判别对照 | 仍需排除 |
|---|---|---|
| 调率利用了延迟信息 | 固定率、同基座元率、因果可得的错位特征 | 平均幅度变化、基础目标变化、额外调参 |
| 记忆保留任务相关历史 | 无记忆、普通 GRU、同状态大小的简单递推、候选记忆 | 更多参数、更多步内计算、隐藏相位输入 |
| GVF 帮助技能选择 | GVF 开/关 × option 开/关 | 额外监督、容量、探索与时长变化 |
| 模型与规划相互帮助 | 固定/在线模型 × 无/有规划 | 模型内幻觉、额外算力、测试时加预算 |

错位和打乱必须保持因果可用性；若还改变边际分布、频谱或方差，就明确剩余混杂。固定数据实验隔离估计器；闭环实验允许数据分布随行为变化。前者成功后仍要回到后者。完整作者方法继续作为外部强基线，不被共同基座移植或内部消融替代。

## 7. 两个项目如何积累而不互相遮蔽

**StreamRate 主线**先完成写入身份、评价目标、延迟信用和提交时点的核验，再检验率控制是否提供信息增量。随后用“actor 目标 × 率控制”的 2×2 区分目标改善与调率改善。GVF 可以增加合法预测，但必须证明被元层使用；规划或大记忆不应掩盖尚未解释的基础更新问题。

**表征与记忆主线**先比便宜编码，再把跨步持久状态与步内计算分开，之后验证共享，最后研究特殊拓扑。用延迟 cue 检查历史需求，用普通 RNN 与简单递推给强对手；再接一个明确消费者，例如固定 GVF 或固定 option 控制器。有效秩、稀疏度、梯度健康等是诊断，不能替代新规则控制能力。

共同生命期采用静态保持、隐藏变化、旧 A 回访与新 C，研究者日程不送入 agent。A 回访区分保留与重学，新 C 区分复用旧答案与持续获取能力；增加未用于选择的变化幅度、驻留时间和更长生命期，检验年龄效应与资源增长。完整方案见[项目实践](continual-project-playbooks.md)；两个协议仍是外部适配器尚未就绪的开发提案，不是已运行证据。

[`summarize`](../rlworkbench/continual_metrics.py) 实现原始生命期、分段与预定窗口恢复诊断。它区分完整观察未恢复、行政删失和 crash；窗口不是额外 seed，阈值也未必在新任务可达。测试 [`test_completed_nonrecovery_censoring_and_crash_are_distinct`](../tests/test_continual_metrics.py) 核对这一边界。该函数不实现遗忘、可塑性或生存模型推断的全部统计分析。

## 8. 多智能体把信息与信用再分一层

环境中的多个行动者、agent 内部多个模块、工程中的多个 worker 必须区分。CTDE 的中央训练信息是否合法由任务制度决定，部署 actor 仍需遵守局部历史和通信权限。团队信用、网络模块信用和学习控制元信用对应不同干预对象，不能凭一个注意力权重就同时解释三者。

先固定队友验证单模块，再加入隐藏换队友，最后放开共同学习。保存独立训练团队的 cross-play 矩阵与冻结对手池；同一团队的队员和比赛不是新的训练重复。原始交互、联合步、agent 动作、通信和规划分别计量。当前 `compare` 面向固定任务的 paired-seed 比较，不提供交叉人口随机效应；[MARL 专题](multi-agent.md)明确外部接入和缺口。

## 9. 让每轮结果改变下一项研究决定

按研究卡记录机制、竞争解释和撤回条件；最小实验若未观察到预测差异，先判断测量精度和实现资格，再修订解释。局部成立后锁定完整选择程序，在新的完整生命期确认外部收益、失败与成本。继续、修订、确认、停止都应引用实际证据；改变理论假设时，不默认继承旧版本的效能结论。

[`core.next_protocol`](../rlworkbench/core.py) 只根据明确决策生成下一版草案；[`WorkflowTests.test_next_never_runs_and_confirmation_uses_reserved_seeds`](../tests/test_workflow.py) 检查它不自动运行。保留种子不证明未来任务隔离，锁定哈希不证明科学设计正确。人类负责主张与资源决定，agent 可以照相同文件执行有边界的工作，并对未实现部分清楚报缺。
